## I. Постановка задачи

**Цель работы:** разработка шаблонного класса AVL-дерева на C++, реализующего интерфейс коллекции, с поддержкой базовых операций дерева, обходов, сериализации, десериализации и извлечения поддеревьев
## II. Функциональные требования
#### 1. Базовые операции дерева
- Вставка в дерево
- Удаление из дерева
- Проверка на содержание элемента в дереве
- Извлечение поддерева
#### 2. Особенности AVL
- Балансировка (4 случая поворота: RR, LL, RL, LR)
#### 3. Обходы
- Поддержка 6 порядков обхода дерева (KLP, KPL, LKP, LPK, PKL, PLK)
-  *Возможность обобщения на большее количество обходов*
#### 4. Функции высшего порядка
- Реализация map
- Реализация where
- Реализация reduce
#### 5. Сериализация
- Возможность сохранять дерево в строку с учетом выбранного обхода  в формате `{K}(L)[R]`, где

	K - корень дерева (фигурные скобки)
	L - левое поддерево (круглые скобки)
	R - правое поддерево (квадратные скобки)
#### 6. Десериализация
-  Восстановление дерева по строке, удовлетворяющей формату из пункта 5
#### 7. Бенчмарк
- Возможность запуска бенчмарка для проверки времени реализации на разных входных данных
#### 8. Пользовательский интерфейс
- Предоставляется в консольном формате
- Предоставляет пользователю возможность выполнения базовых операций над деревом, просмотра дерева и запуска бенчмарка
#### 9. Обработка исключений
- Могут выбрасываться исключения в случае передачи невалидных аргументов или нулевого указателя (Удаление несуществующего элемента, неверный формат строки, передача нулевого указателя на функцию)
## III. Нефункциональные требования

#### 1. Стек и ограничения
- Необходимая версия стандарта - C++17 и выше
- Тестирование осуществляется через GoogleTest
- Сборка осуществляется через CMake
- Использование std::unique_ptr для управление памятью
- Использование исключений и базовых контейнеров (Sequence), реализованных в лабораторных работах второго семестра
- Система сохраняет работоспособность при росте количества элементов
#### 2. Сложность операций
- Благодаря балансировке AVL-дерева для операций вставки, удаления и поиска поддерживается сложность O(LogN)
- Для обхода сложность O(N)
*N - количество узлов в дереве*
#### 3. Реализация интерфейсов (Архитектурные ограничения)
-  AVLTree наследуется от ICollection
- Итератор наследуется от IEnumerator
#### 4. Оценка качества реализации
- Покрытие модульными тестами с помощью библиотеки GoogleTest
- Бенчмарк замеряет время, необходимое для операций на данных объема 10^4, 10^5, 10^6

##### Контейнер AVLTree
